# Crown-scale canopy deciduousness from UAV time series in Central Africa

Code for the article *Continuous UAV monitoring across canopy observatories reveals diversity and
climatic control of canopy deciduousness in Central Africa* (Plumacker et al., in review).

Two to nearly three years of UAV RGB acquisitions (target revisit: two weeks) at three sites of the
[CanObs](https://www.canobs.net) network (Luki and Yangambi, DR Congo; Mbalmayo, Cameroon) are turned
into leaf-presence probability maps with DINOv2 features and a logistic regression, summarised per
tree crown (23,119 crowns), and described by three metrics of leaf loss (magnitude, timing,
duration) and by the synchrony of leaf loss at each site.

## Reproducing the analyses (figures 3, 5, 6, S1, S2 and tables 2, 3, S1, S2)

1. Obtain the data folder `Article_canopy_deciduousness_data` (University of Liège data repository, see *Data availability*)
   and copy its content into `data/` (or point the environment variable `DATA_DIR` to it).
2. Install the dependencies (Python ≥ 3.10): `pip install -r requirements.txt`
   (only the first block is needed for `analysis/`).
3. Run `bash analysis/run_all.sh`. Outputs are written to `results/` (or `RESULTS_DIR`); the whole
   sequence takes a few minutes on a laptop.

The scripts of `analysis/` reproduce the published values exactly from the data release
(checked against the manuscript tables and figures). `pipeline/04` reproduces the cross-validation
metrics (AUC-ROC 0.855, macro-F1 0.753) and the coefficients of the shipped model from
`photointerpretation_points_features.csv.gz`.

## Processing chain (pipeline/)

The pipeline needs the orthomosaics, which are not part of the data release (see *Data
availability*). Expected layout under `raw/` (or `RAW_DIR`):

```
raw/orthomosaics/<site>/<YYYYMMDD>*.tif          RGB orthomosaics (Time-SIFT, co-registered with AROSICS)
raw/dinov2_features/<site>/<YYYYMMDD>_features.tif    written by 01
raw/photointerpretation/<site>/*<YYYYMMDD>*.gpkg     points, column II_default (L, R, D, NA)
raw/leaf_probability/<site>/<YYYYMMDD>_proba_L.tif   written by 05
raw/dtm/<site>/dtm.tif                           1-m LiDAR DTM (terrain rasters written next to it by 07a)
```

1. `01_extract_dinov2_features.py`: DINOv2-ViT-S/14, 518 × 518-pixel tiles, 126-pixel overlap;
   one 384-dimensional vector per 14 × 14-pixel patch (0.7 m).
2. `02_point_features.py`: features at the photo-interpreted points (label 1 = leaves absent).
3. `03_select_C_nested_cv.py`: choice of C by nested cross-validation grouped by date.
4. `04_train_evaluate_model.py`: 5-fold cross-validation grouped by acquisition date (Fig. 4) and
   final model on all points.
5. `05_predict_leaf_probability.py`: leaf-presence probability map for every date.
6. `06_crown_timeseries.py`: per-crown summaries of the maps (2-m inner buffer, ≥ 5 valid cells);
   `q90` is the crown leaf presence used in all analyses.
7. `07a_terrain_rasters.R`, `07b_field_crown_topography.py`: terrain descriptors of the field crowns.

Crowns were delineated with Detectree2SAM (Plumacker et al., 2026); the released polygons are
those of the analysed crowns.

## Data availability

- **Data (`Article2_data`, University of Liège data repository, available from the authors on request):** per-crown leaf-presence time series, crown metrics,
  crown polygons, species and leaf habit of the field-identified crowns, terrain descriptors,
  daily climate series, DINOv2 features and labels of the photo-interpreted points, and a document
  showing the leaf-presence probability map of every acquisition. See `docs/DATA_README.md` (also in the data folder).
- **Model:** `model/leaf_presence_logreg.joblib` (dictionary with the fitted `model`, `scaler` and
  `feature_cols`); positive class = leaf absence, leaf-presence probability = 1 − p.
- **Orthomosaics and probability rasters:** available through the CanObs network
  (https://www.canobs.net) on request.

## Notes

- Site names: `Luki`, `Mbalmayo`, `Yangambi`. Dates are `YYYYMMDD`.
- `crown_id` identifies a crown within a site and within its set (all crowns vs field crowns).
- Randomness: the only random steps (null model of φ, noise simulation) use fixed seeds.
